## 逐个方案说明

### 01 墨黑极简 · Linear / Vercel
近纯黑底（`#08090A`），**零边框**，完全靠底色亮度差分层。字色接近纯白，字距收紧。
- 适合：追求"高级感"、不在意工具感
- 代价：纯黑底长时间看有轻微拖影感，OLED 屏更明显
- 现代表现力最强的一个

### 02 石板·编辑器 · VS Code Dark+
最"工具"的一个：方正 2px 圆角、1px 描边、8px 间距，密度最高。
- 适合：习惯 VS Code、要一屏塞更多行
- 代价：**主色偏暗（2.28:1）**，按钮和选中态存在感弱；视觉上显旧

### 03 深蓝夜 · Night Owl / Raycast
蓝调底（`#0F1729`），冷感、专业。蓝光是 10 个里最高的（52%）。
- 适合：白天使用、喜欢冷色调
- 代价：夜间/长时间用眼偏累

### 04 暖炭·护眼 · Anthropic 暖灰
暖棕灰底（`#1A1714`），蓝光占比 29%，是暗色里最低的。
- 适合：**长时间盯屏**、夜间作业，这是它唯一但足够强的优势
- 代价：橙色强调不如蓝色"科技感"，需要接受偏人文的调性

### 05 玻璃拟态 · Figma / macOS
12px 大圆角 + 边框高光，层次最丰富、最"现代 UI"。
- 适合：想要 Figma 那种精致感
- 代价：真玻璃需要半透明合成，**Qt QSS 只能近似**（我已改实色模拟）；
  圆角大占空间，密集布局下会显得松散

### 06 亮色·清爽 · Notion
纯白卡片 + 浅灰底（`#FBFBFC`）。白天办公最舒服。
- 适合：白天主力、打印/截图交付给客户
- 代价：与 `PRODUCT.md` 的"深色品牌基础"冲突；夜间刺眼

### 07 高对比·无障碍 · WCAG AAA
纯黑底 + 纯白字，对比度 19.7:1（远超 AA）。
- 适合：视力不佳、老花、强光环境
- 代价：观感偏"硬"，缺乏层次，长时间看容易疲劳

### 08 深紫·创意 · 剪映风
紫调底，有设计感。适合内容创作类产品。
- 适合：想强调"创意工具"属性
- 代价：紫色在色彩心理学上偏女性化/娱乐化，可能削弱"专业生产工具"印象

### 09 青灰·工业 · 工业软件风
青绿灰底，冷峻、不讨好。工业/刀塔类软件的经典调性。
- 适合：强调稳定、专业、不出错
- 代价：偏冷硬，不够亲和

### 10 米白·纸感 · Bear
暖白底（`#F5F2ED`），像纸。柔和、人文。
- 适合：想要独特气质、长时间阅读型工作
- 代价：同样与"深色专业工作台"的品牌设定冲突

## 我的推荐（按你的使用场景）

你的产品是**电商批量制图工具，用户长时间盯屏、频繁切换素材**。按这个前提：

**第一梯队**
1. **04 暖炭·护眼** —— 蓝光最低（29%），长时间用眼最舒服；暖调在暗色里少见，有辨识度
2. **01 墨黑极简** —— 现代感最强，零边框的思路正好治掉旧界面"满屏边框"的病
3. **03 深蓝夜** —— 如果你更想要"科技感/专业感"，这个比 01 更有工具气质

**不推荐**
- **02**：主色不达标，视觉显旧，等于退了半步
- **07**：对比度拉太满，日常使用显硬
- **06 / 10**：与"深色品牌基础"的定位冲突，除非你决定改产品定位

**如果让我只选一个：04 暖炭·护眼。**
理由不是审美，是使用场景匹配——电商运营一天盯屏 8 小时，蓝光低 + 暖调的优势会持续兑现，
而"科技感"只在第一次打开时有用。

## 选完之后怎么落地

1. 你选定一个编号
2. 我把该方案的取值写进 `app/ui/tokens_v2.py`（已有版本，只需替换 Palette）
3. 52 项设计契约测试会立刻验证它是否真达标
4. 然后进入 P1/P2 落地（`design_tokens.py` 转发 + `provider.py` 接新令牌）

**换方案的成本很低** —— 令牌是集中定义的，换色只改一个文件。

### 落地过程中发现的三个真实缺陷

**1. 工具栏按钮图标与文字重叠**
`provider.py` 里 `QPushButton[variant]` 与 `QToolButton[variant]` 共用一条规则，
都设了 `height: 36px`。但工具栏 `QToolButton` 是 `TextBesideIcon` 且工具栏仅 ~33px 高，
按钮被撑到 36px 后图标和文字挤在一起。
→ 拆分规则：QToolButton 用 `min-height: 24px; padding: 1px 7px`。

**2. 侧栏仍停留在旧主色**
`design_tokens.py` 里 `SIDEBAR_COLOR_PRIMARY = ACCENT` 是**类定义时按值绑定**的。
我的 v2 覆盖在类定义之后执行，不会自动刷新这些派生值 ——
结果主色已变成 `#5E6AD2`，侧栏却还是 `#2F9CF4`。
→ 覆盖后对派生令牌做二次 `setattr` 同步。

**3. 布局尺寸被配色变更误伤**
我最初把 `CARD_RADIUS` / `CONTROL_RADIUS` / `SECTION_GAP` 等也接到 v2，
导致 `PropertyPanelA2.CARD_RADIUS` 从 7 变 8，破坏了面板尺寸契约测试。
→ 撤回：**布局尺寸属于结构契约，不该由配色方向左右**。v2 只覆盖颜色与字体。
