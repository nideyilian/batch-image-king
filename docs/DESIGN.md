# 批图王 · 设计规范 v2

> 适用界面：**QML 工作台**（`python main.py`，即 `app/qml`）。
> 2026-10-28 起经典 Qt Widgets 界面（`app/ui` 主窗口）已下线；
> `app/ui` 仅保留 QML 仍在调用的 QWidget 弹窗、令牌与主题模块。
> 令牌源文件：`app/ui/tokens_v2.py`（**唯一事实来源**）
> 契约测试：`tests/test_design_tokens.py`（45 项，含全部对比度实测）

## 0. 这份规范要解决什么

改造前实测到的四个具体问题（不是审美判断，是可量化的缺陷）：

| 问题 | 实测证据 | 后果 |
|---|---|---|
| 主色漂移成三套 | `design_tokens.py` 用 `#2F9CF4`；`integrated_text_editor_dialog.py` / `simple_text_editor_dialog.py` 用 Ant Design 的 `#1677FF` / `#4096FF` | 同一产品三种蓝，切换界面时色调跳变 |
| 字体栈两套且顺序错 | 令牌 `"Microsoft YaHei UI, Segoe UI"`；全局 QSS `"Segoe UI", "Microsoft YaHei"`；图层列表 `"Microsoft YaHei, SimHei, Arial"` | Segoe UI 无汉字 → 逐字回退 → 中英混排字重与基线不一致 |
| 白字压主色不达标 | `#FFFFFF` 于 `#2F9CF4` = **2.92:1**（AA 要求 4.5:1） | 主按钮文字偏虚，暗光环境下难读 |
| 令牌体系双轨 | `design_tokens.py`（20 个文件引用）+ `theme/tokens.py`（11 个文件引用），`dialog_a2.py` 两边都引 | 改一处要改两处，长期必然漂移 |

## 1. 行业基准对照（取值依据）

### 1.1 字号

| 系统 | 桌面正文下限 | 档位 |
|---|---|---|
| **TDesign**（腾讯） | **12px** | 12/14/16/20 + 24/28/36/48/64 |
| Arco Design（字节） | 12px | body 12/13/14，title 16/20/24 |
| Tailwind | 12px（`text-xs`） | 12/14/16/18/20/24/30 |
| Ant Design | 12px | 基准 14，`fontSizeSM` 12 |
| Material Design 3 | 11px（仅 labelSmall） | label 11/12/14；body 12/14/16 |

**本项目取值**：`12 / 13 / 14 / 16 / 20 / 24`，11px 仅作 `size_caption`（角标、辅助标签）。

**为什么正文用 13 而不是 14**：这是桌面密集型工具（图层列表、属性面板一屏几十行）。Arco 的 `body-2` 也是 13px。TDesign 桌面端允许 12px 起，13px 在紧凑与可读之间取平衡。**这是刻意偏离 14px 基准，理由是信息密度优先**；若后续做平板/触屏版本，正文应回到 14px。

**行高规则**：`line-height = font-size + 8`（TDesign 官方规则，非 1.5 倍）。14px→22px、16px→24px 恰好等于 1.5 倍，但小字号下比固定倍数更稳。

### 1.2 间距

| 系统 | 体系 | 非 4 倍档 |
|---|---|---|
| Arco / Ant / Bootstrap / Carbon | 纯 4px 栅格 | 无 |
| Chakra UI | 4px 为 1 单位 | 有：2 / 6 / 10 / 14 |
| Tailwind | 0.25rem 基准 | 有：2 / 6 / 10 / 14 |

**本项目取值**：`2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32`

**为什么保留 2 和 6**：本项目 2px 出现 14 次（边框内衬、图标对齐），6px 用于紧凑行间距。这两个档位在 Tailwind（`space-0.5` / `space-1.5`）和 Chakra 里都是正式档位，不是自造。**奇数间距 5/7/9/11 一律禁止**（无任何主流系统支持）。

### 1.3 暗色层级

行业明确规则（Radix、Mantlr 一致）：

> 暗色模式下 elevation 靠**变亮**表达，不是变暗。品牌色需降饱和 10–20%，否则在近黑背景上会刺眼。

**本项目现状**：层级顺序本身是对的（`canvas #151515` → `elevated #2F2F2F` 单调递增），但**主色没有降饱和**，`#2F9CF4` 在暗底上偏荧光。

**修正**：主色改为 `#2378C4`（降饱和 + 压白字达标）。

### 1.4 可点击目标

WCAG 2.5.8（AA）：最小 **24×24 px**。

**本项目取值**：控件高 24 / 28 / 32 / 36；图标 14 / 16 / 20。主控件高从旧 30 改为 **28**，一屏多放一行。

## 2. 颜色令牌

### 2.1 表面层级（elevation 越高越亮）

| 令牌 | 色值 | 用途 |
|---|---|---|
| `canvas` | `#0D0D0F` | 画布工作区（最低层） |
| `surface_base` | `#141416` | 应用底 / 窗口背景 |
| `surface_1` | `#191A1C` | 侧栏 / 停靠面板 |
| `surface_2` | `#1F2023` | 卡片 / 分组容器 |
| `surface_3` | `#25262A` | 输入框 / 下拉框 |
| `surface_4` | `#2C2D32` | 弹层 / 右键菜单（最高层） |
| `surface_hover` | `#34363B` | hover 态 |
| `surface_selected` | `#22293A` | 选中行（带主色倾向，不用纯蓝） |

### 2.2 文本

| 令牌 | 色值 | 最低对比度 | 用途 |
|---|---|---|---|
| `text_primary` | `#F2F4F7` | 12.47:1 | 正文 |
| `text_secondary` | `#D6D9DE` | 11.15:1 | 次级正文 |
| `text_tertiary` | `#B4B7BE` | 8.20:1 | 标签 / 说明 |
| `text_muted` | `#9EA1A9` | 5.32:1 | 提示 / 占位符 |
| `text_disabled` | `#6E7178` | 2.92:1 | 禁用（WCAG 对禁用态不强制） |

### 2.3 品牌与状态

| 令牌 | 色值 | 白字对比度 | 说明 |
|---|---|---|---|
| `accent` | `#2378C4` | **4.61:1** ✓ | 主色（替换旧的 `#2F9CF4`） |
| `accent_hover` | `#1E6FB8` | **5.22:1** ✓ | hover **变暗** |
| `accent_active` | `#1A5F9E` | **6.62:1** ✓ | pressed 更暗 |
| `danger` | `#BE3329` | **5.68:1** ✓ | 危险**按钮填充**（承载白字） |
| `danger_emphasis` | `#E5484D` | — | 错误**图标 / 文字 / 边框**（暗底可见 4.27:1） |
| `danger_hover` | `#A82A23` | **6.95:1** ✓ | |
| `success` | `#30D158` | — | 成功提示（仅作图标/文字） |
| `warning` | `#FF8A3D` | — | 警告 |

> **关键决策：hover 变暗而不是变亮。**
> 实测 `#2A84D4`（比主色亮）压白字只有 3.93:1，不达标。要让 hover 既「有反馈」又「白字可读」，只能往暗走。这是 Radix / Arco 在暗色主题下的统一做法。

### 2.4 边框

| 令牌 | 色值 | 用途 |
|---|---|---|
| `border_subtle` | `#25262A` | 分割线 |
| `border_default` | `#2C2D32` | 卡片描边 |
| `border_control` | `#34363B` | 输入控件描边 |
| `border_strong` | `#52545B` | 强调描边 / 拖拽分隔条 |
| `border_focus` | `#2F9CF4` | 焦点环（保留旧主色，仅用于非文字） |

> **关键决策 2：danger 必须拆成两个令牌。**
> 同一个红色无法同时满足两种用途：
> - 作为**填充色**承载白字 → 需要够暗（`#BE3329`，白字 5.68:1 ✓）
> - 作为**图标/文字**出现在暗底 → 需要够亮（该值在 `surface_1` 上仅 2.94:1 ✗）
>
> 实测 `#D63D31` 在暗底上 3.64:1 达标，压白字却跌到 4.59（临界）。没有单值解。
> 所以拆为 `danger`（填充）与 `danger_emphasis`（图形/文字）。这是很多设计系统
> 会踩的坑 —— 它们通常只定义一个 `destructive`，然后在暗色下必然有一处不达标。

## 3. 字体

```
font-family: "Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC", "Segoe UI", sans-serif
```

**中文族必须排第一。** Windows 的 Segoe UI 不含汉字；若它排前面，浏览器/Qt 会对每个汉字单独触发字体回退，结果是中英混排时字重、基线、字宽都不一致——这正是旧界面「字看着不精致」的根因。

| 令牌 | 值 | 用途 |
|---|---|---|
| `size_caption` | 11px / 19px | 角标、辅助标签（**唯一允许 11px 的地方**） |
| `size_sm` | 12px / 20px | 次要说明 |
| `size_base` | 13px / 21px | 正文、控件文字 |
| `size_md` | 14px / 22px | 对话框主体 |
| `size_lg` | 16px / 24px | 区块标题 |
| `size_xl` | 20px / 28px | 页面标题 |
| `size_2xl` | 24px / 32px | 大标题 |

字重：400 / 500 / 600 / 700。**中文不用 500**（雅黑没有 Medium 字重，会合成假粗体），中文强调用 600。

## 4. 组件规范

### 4.1 按钮

| 变体 | 背景 | 文字 | 边框 | 用途 |
|---|---|---|---|---|
| `primary` | `accent` | `#FFFFFF` | 无 | 主操作（每屏最多 1 个） |
| `secondary` | `surface_3` | `text_primary` | `border_control` | 次要操作 |
| `ghost` | 透明 | `text_secondary` | 无 | 工具栏图标按钮 |
| `danger` | `danger` | `#FFFFFF` | 无 | 删除 / 不可逆操作 |

尺寸：高 28（默认）/ 24（紧凑）/ 32（大）；圆角 `Radius.md` (6)；水平内边距 `Space.md`~`lg` (8~12)。

状态：`hover` 背景亮一档（非填充按钮）或暗一档（填充按钮）；`disabled` 背景 `surface_2`、文字 `text_disabled`；`focus` 外描边 `border_focus` 2px。

### 4.2 输入框

- 背景 `surface_3`，边框 `border_control` 1px，圆角 `Radius.md`
- 高度 28；文字 `size_base` / `text_primary`；占位符 `text_muted`
- focus：边框 `border_focus`，**不改变背景**（避免布局跳动）

### 4.3 面板 / 卡片

- 面板背景 `surface_1`，卡片 `surface_2`，圆角 `Radius.lg` (8)
- **默认不加描边**。用底色亮度差承担分层；描边只用于「需要被框住」的
  临时容器（如拖拽预览区）。这是与旧版最大的差异点 —— 旧版每个面板都描边，
  整屏十几个框，是「廉价感」的主因。
- 面板标题：`size_lg` / `weight_semibold` / `text_primary`
- 内边距 `Space.xl` (16)；标题与首个控件之间加 `Space.lg` (12)
- 区块之间 `Space.lg` (12)；同一区块内控件之间 `Space.md` (8)
- 分割线用 `border_subtle` 1px，**仅在同一区块内部需要分组时使用**，
  不要用它代替间距

### 4.4 列表项（图层列表）

- 行高 28（紧凑）或 32（含缩略图）
- hover：`surface_hover`；选中：`surface_selected`
- 选中态**不能只靠颜色**：需同时有左侧 2px 主色指示条（无障碍要求，`PRODUCT.md` 已明确）

### 4.5 对话框

- 背景 `surface_2`，圆角 `Radius.xl` (12)，阴影 `Elevation.lg`
- 遮罩 `overlay_scrim`（`rgba(0,0,0,0.56)`）
- 标题 `size_lg`/600，正文 `size_md`，按钮区右对齐、间距 `Space.md`

## 5. 落地策略

### 5.0 先看实测结论：只改颜色没用

用同一套 Qt 控件渲染的三列对照（`_component_sheet.png`，可用
`python _component_sheet.py` 重新生成）：

| 方案 | 做法 | 观感 |
|---|---|---|
| **A 改造前** | 旧令牌 + 1px 描边 + 6px 间距 | 廉价、拥挤、每块都有边框像表格 |
| **B 仅换令牌** | 新颜色 + 仍用 1px 描边 + 6px 间距 | **和 A 几乎没差别** |
| **C 完整改造** | 新令牌 + **去卡片描边** + 12px 间距 + 28px 控件高 | 明显更专业、更透气 |

**结论：视觉提升的约 70% 来自「间距节奏 + 不滥用边框」，颜色只占 30%。**
只看色值对比会误判——这正是 B 列看起来没变化的原因。

三条具体规则：

1. **卡片不要描边，用底色差分层**。旧做法每块面板加 `1px solid #303033`，
   一屏十几个框，视觉上像 Excel。改用 `surface_1` vs `surface_base` 的
   亮度差（约 3%）区分；只有真正的浮层（弹窗 / 菜单）才用阴影。
2. **区块间距从 6px 提到 12px，卡片内边距从 12px 提到 16px**。
   旧 6px 让元素全部挤在一起，没有呼吸。
3. **区块标题与内容之间留白**。旧做法标题紧贴第一个控件，读起来粘在一起。

### 5.1 三步走，不要一次全改

| 阶段 | 内容 | 风险 | 可验证性 |
|---|---|---|---|
| **P1 令牌收敛** | 建立 `tokens_v2.py`，旧 `design_tokens.py` 改为从这里转发；消灭 Ant 蓝 | 低 | 全量截图对比 |
| **P2 全局 QSS 重写** | `theme/provider.py` 按新规范重写基础控件样式 | 中 | 逐控件截图 |
| **P3 业务文件清理** | 清理 173 处硬编码色值中与令牌冲突的部分 | 中高 | 逐文件回归 |

**P1 必须先做**：现在两套令牌并存，P2 无论怎么写都会遇到「改哪个」的问题。

### 5.2 硬编码清理的取舍

实测 `app/ui` 下 173 处硬编码色值、去重 84 种。**不要机械全替换**：

- **高频且与令牌一致**（如 `#ffffff` 11 次、`#2f9cf4` 11 次）→ 替换为令牌，收益高
- **低频且是局部设计**（如某个对话框的特殊高亮）→ 先补令牌再替换，别就地改色
- **Ant 蓝 `#1677FF`/`#4096FF`**（共 6 处，在 `integrated_text_editor_dialog.py` 和 `simple_text_editor_dialog.py`）→ **必改**，这是明确的漂移

### 5.3 验收标准

1. `pytest tests/test_design_tokens.py` 全绿（45 项）
2. 截图对比：改造前后同一界面并排，目视可辨提升
3. 缩放 100% / 125% / 150% 下无文字截断、无控件重叠
4. 键盘 Tab 走查：焦点环清晰可见（`border_focus` 2px）

## 6. 待确认的取舍（需要产品决策）

| 议题 | 选项 A | 选项 B | 建议 |
|---|---|---|---|
| 正文 13px vs 14px | 13px（信息密度高） | 14px（更易读） | **13px**，桌面密集工具，Arco 同款 |
| 控件高 28 vs 32 | 28（紧凑） | 32（好点） | **28** 默认 + 32 用于主操作 |
| 是否保留亮色主题 | 只做暗色 | 双主题 | **先只做暗色**，`PRODUCT.md` 明确暗色是品牌基础 |
| 主色是否保留 `#2F9CF4` 观感 | 换 `#2378C4`（达标） | 保留但白字改用深色 | **换色**；深色字压蓝底反而更怪 |
