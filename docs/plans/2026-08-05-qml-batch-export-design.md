# QML 批量导出工作流设计

## 目标

把 QML 工作台从“只能导出当前画面”推进到可实际使用的批量生产工作流，同时继续复用 `Document.batch_export()` 的随机取图、图层绑定、智能采样、缓存治理与独立导出进程能力。

## 交互设计

顶部主操作改为“批量导出”，点击后从右侧打开固定宽度的导出抽屉。抽屉不是独立设置页，而是当前文档的任务面板，包含输出目录、生成数量、文件名模板、格式和避免重复选项。单图导出保留在主按钮旁的图标按钮中，避免降低原有工作流效率。

导出启动后，参数区域保持可见但不可编辑，主体切换为任务状态：当前阶段、完成数量、进度条和最近生成文件。主按钮变为“取消导出”。取消只停止后续任务，不清理已经生成的文件。完成、取消和失败分别使用成功色、警示色和错误色，并提供“打开目录”和“再次导出”动作。

抽屉使用现有暗色设计令牌，保持 6 px 以内圆角、紧凑控件和清晰的信息层级。格式选择采用分段控件，二元设置采用开关，目录选择使用 `FolderDialog`。键盘焦点、悬停、禁用和错误状态均有明确反馈。

## 架构

新增 `BatchExportViewModel`，独立管理导出参数和状态，不继续扩大 `WorkspaceViewModel`。它持有当前 `Document` 引用，监听 `export_progress_updated`、`file_exported` 和 `export_stage_updated` 信号，并通过 `QThreadPool` 执行阻塞的 `Document.batch_export()`。

`WorkspaceViewModel` 新增文档对象变更信号和导出锁定状态。批量任务开始时禁止新建、打开、图层编辑、撤销/重做和单图导出；任务结束后恢复。后台任务与预览共用同一把文档锁，防止渲染和导出并发修改临时图层状态。

## 数据流

```text
QML 导出抽屉
  -> BatchExportViewModel 参数校验
  -> QRunnable + Workspace 文档锁
  -> Document.batch_export()
  -> 现有高性能执行器 / 独立导出进程
  -> Document 进度、阶段、文件信号
  -> BatchExportViewModel 状态属性
  -> QML 实时反馈
```

## 错误与取消

- 数量限制为 1 到 10000，输出目录和文件名模板不能为空。
- 输出目录在任务启动前创建；创建失败直接显示错误，不启动线程。
- 后台异常统一转为失败状态，并优先展示 `Document._last_export_error`。
- 取消使用线程安全事件，并调用 `Document.cancel_export()` 加速传播。
- 文档切换仅在非运行状态允许；切换后 ViewModel 自动断开旧信号并连接新文档。

## 验收标准

- QML 可选择目录并发起真实批量导出。
- 进度、阶段、当前数量和最近文件实时更新。
- 导出运行期间不能修改或切换文档。
- 可取消任务，已输出文件保留。
- 单图导出仍可用。
- ViewModel 单元测试、QML 离屏烟雾测试和现有 QML 桥接测试通过。
