# QML 参数模块重复与冲突审计及修复方案

**日期：** 2026-08-07
**状态：** 分析完成，待实施
**范围：** `app/qml/Main.qml` 右侧图层属性检查器，以及直接关联的 `WorkspaceViewModel`、图层字段和渲染分支。
**本轮限制：** 只形成修复文档，不修改现有功能代码。

## 一、审计目标

本次审计延续“图像源不再同时提供模式切换和来源选择”的原则，检查其他参数模块是否存在以下问题：

1. 同一状态被模式、开关、状态文字或多个分区重复表达。
2. 两个互斥布尔值实际表示一个枚举模式。
3. 参数可由上下文自动判断，却仍要求用户手动选择。
4. 控件可见但当前上下文中不参与渲染，形成无效入口。
5. 同一模型字段存在多个编辑入口，但没有明确区分“精确输入”和“快捷预设”。

## 二、审计方法与结论摘要

检查器当前包含 22 个 `PropertySection` 和 84 个 `InspectorRow`。审计同时核对了：

- QML 控件的 `visible`、`checked`、`active` 和提交方法。
- `WorkspaceViewModel` 的属性和写入槽函数。
- 图层模型、矢量轮廓、圆角和分身渲染分支。
- 相关 QML 单元测试和既有设计文档。
- 一次运行时像素探针，用于验证圆角参数是否真正改变输出。

共确认 8 项需要处理的问题：

| 优先级 | 数量 | 说明 |
| --- | ---: | --- |
| P1 | 3 | 状态建模重复、控件无效或模式互斥却分散表达 |
| P2 | 4 | 术语冲突、重复状态文字、重复只读信息 |
| P3 | 1 | 可进一步统一的控件呈现 |

没有发现阻断任务完成的 P0 问题。

## 三、统一判断规则

后续修复应遵循以下规则：

1. **一个业务状态只有一个主编辑入口。**
2. **互斥状态使用分段模式或下拉选择，不使用多个独立开关。**
3. **真正的启用/停用状态使用开关，不再额外显示“已开启/已关闭”。**
4. **开关两侧都代表有意义工作模式时，改用分段控件。**
5. **只在参数实际参与当前渲染分支时展示控件。**
6. **精确值和快捷预设可以共存，但必须明显属于同一个参数。**
7. **分区摘要用于折叠后查看状态，不应成为额外编辑入口。**
8. **不修改 `.cmp` 序列化字段，优先在 ViewModel 增加语义清晰的界面门面。**

## 四、详细问题

### P1-1 颜色叠加和渐变叠加实际是同一个互斥模式

**位置：**

- `app/qml/Main.qml:6581`，颜色叠加分区。
- `app/qml/Main.qml:6640`，渐变叠加分区。
- `app/qml/viewmodels/workspace_view_model.py:4605`。
- `app/qml/viewmodels/workspace_view_model.py:4644`。

**现状：**

界面把颜色叠加和渐变叠加显示为两个独立分区、两个独立启用开关，但 ViewModel 在开启其中一个时会自动关闭另一个。底层实际状态是：

```text
关闭 / 颜色叠加 / 渐变叠加
```

而不是两个可以独立组合的布尔效果。

**影响：**

- 用户看见两个独立开关，会自然预期两种效果可以叠加。
- 开启第二项会静默关闭第一项，造成设置“被程序改回去”的感受。
- 两个分区重复颜色、强度和启用结构，增加滚动长度。

**修复方案：**

1. 合并为单一“颜色叠加”分区。
2. 增加模式选择：`关闭 / 纯色 / 渐变`。
3. `纯色` 模式显示颜色和强度。
4. `渐变` 模式显示起始色、结束色、强度、角度和方向预设。
5. ViewModel 增加语义门面：
   - `selectedOverlayMode`
   - `setSelectedOverlayMode(mode)`
6. 底层继续保存现有 `color_overlay_enabled` 和 `gradient_overlay_enabled`，不改变 `.cmp` 格式。
7. 旧的两个 setter 可暂时保留为兼容入口，并委托给新模式方法。

**参考实现：**

现有“文字填充”已经使用 `纯色 / 渐变` 单一模式，是可直接复用的信息架构。

### P1-2 圆角模块存在重复入口和无效控件

**位置：**

- `app/qml/Main.qml:5233`，多边形圆角。
- `app/qml/Main.qml:6776`，通用圆角分区。
- `app/qml/viewmodels/workspace_view_model.py:749`。
- `app/qml/viewmodels/workspace_view_model.py:1284`。
- `app/utils/vector_layer_geometry.py:63`。
- `app/utils/vector_layer_geometry.py:408`。

**现状：**

圆角相关字段至少包含三组：

- `corner_radius`
- 四个 `vector_corner_radius_*`
- `polygon_corner_radius`

当前 QML 仅按“对象是否具有字段”决定是否显示通用圆角分区，没有判断当前形状和路径模式是否真正使用该字段。

运行时像素探针确认：

| 当前对象 | 修改 `corner_radius` | 修改 `polygon_corner_radius` |
| --- | --- | --- |
| 矩形 | 生效 | 不生效 |
| 直角梯形 | 不生效 | 生效 |
| 圆形 | 不生效 | 不生效 |
| 五边形 | 不生效 | 生效 |
| 六边形 | 不生效 | 生效 |
| 已转换贝塞尔路径 | 不生效 | 不生效 |

矩形还有第二层冲突：四角值任意一个大于 0 后，`corner_radius` 不再参与轮廓计算。因此“半径”和“矢量统一”会变成两个看似都能统一圆角、实际优先级不同的入口。

**影响：**

- 五边形、六边形会同时出现“多边形圆角”和通用“圆角”，但只有前者有效。
- 圆形和贝塞尔路径会显示完全不影响结果的圆角控件。
- 设置过独立四角后，再修改“半径”可能没有任何视觉变化。
- 梯形渲染支持 `polygon_corner_radius`，但当前形状区没有提供对应入口。

**修复方案：**

1. 将圆角编辑按几何类型分流：
   - 普通图片和矩形异形：矩形圆角。
   - 梯形、五边形、六边形：形状顶点圆角。
   - 圆形：不显示圆角。
   - 已转换贝塞尔路径：在实现真实路径圆角前不显示圆角。
2. 矩形圆角只保留一个“统一半径”入口。
3. 增加“独立四角”模式；开启后显示四个角值。
4. 统一半径 setter 同时写入 `corner_radius` 和四个矢量角值，避免优先级残留。
5. 把梯形的顶点圆角补入“形状”分区。
6. 通用圆角分区的可见性不能再只依赖 `hasattr(layer, "corner_radius")`。
7. 可在 ViewModel 增加：
   - `selectedCornerControlKind`
   - `selectedSupportsUniformCorners`
   - `selectedSupportsIndependentCorners`

**数据兼容：**

保留所有既有序列化字段。加载旧文件时按当前字段计算有效圆角，不做破坏性迁移。

### P1-3 分身的“固定行列”和“填充画布”被错误表达为开关

**位置：**

- `app/qml/Main.qml:5872`，图层分身分区。
- `app/qml/Main.qml:6007`，元素铺排开关。
- `app/models/document_render.py:185`。
- `app/utils/fast_renderer_surface.py:1653`。

**现状：**

`clone_fill_enabled` 实际选择两套互斥的布局算法：

```text
固定行列 / 填充画布
```

它不是普通的启用/停用开关。开启填充画布后，渲染器会用 `clone_fill_*` 重新生成位置，固定模式的行数、列数、行距和列距不再参与最终位置计算。

但当前界面仍同时显示：

- 数量：行、列。
- 间距：行距、列距。
- 元素铺排：状态文字加开关。
- 铺排模式、铺排间距、边距和角度。

**影响：**

- 填充画布模式下仍可编辑无效的行列参数。
- “元素铺排”看起来像额外叠加能力，实际会替换固定行列算法。
- 同一分区同时展示两套参数，用户难以判断哪些正在生效。

**修复方案：**

1. 保留“启用分身”作为真正的总开关。
2. 分身启用后增加“布局模式”分段控件：
   - `固定行列`
   - `填充画布`
3. 固定行列模式只显示：
   - 行列数量。
   - 行列间距。
4. 填充画布模式只显示：
   - 排列类型。
   - 元素间距。
   - 边距。
   - 角度。
5. 自定尺寸和镜像属于两种模式的公共参数，继续显示。
6. ViewModel 可增加 `selectedCloneLayoutMode` 和 `setSelectedCloneLayoutMode()`，底层继续映射 `clone_fill_enabled`。

### P2-1 “智能裁剪”与“填满裁剪”术语冲突

**位置：**

- `app/qml/Main.qml:52`，适配模式包含“填满裁剪”。
- `app/qml/Main.qml:5055`，独立“智能裁剪”开关。
- `app/qml/viewmodels/workspace_view_model.py:3758`。
- `app/models/layer_image_source_mixin.py:315`。

**现状：**

界面同时出现：

- `填满裁剪`：等比缩放后裁剪到图层尺寸。
- `智能裁剪`：实际写入 `use_original_size`，行为是裁掉透明边界后再执行适配。
- 开关的无障碍名称却是“使用原始尺寸”。
- 适配下拉中又存在真正的“原始尺寸”模式。

这是三个不同概念共用了“裁剪”和“原始尺寸”术语。

**影响：**

- 用户无法预测两个裁剪设置的先后关系。
- “使用原始尺寸”与适配模式“原始尺寸”看起来重复。
- 对没有 Alpha 通道的普通 JPG，该开关通常不会产生可见效果。

**修复方案：**

1. 将 QML 文案改为“去透明留白”或“裁透明边”。
2. 状态说明改为“忽略透明外边 / 保留完整画面”。
3. 无障碍名称同步改为“去除图片透明留白”。
4. ViewModel 可增加语义别名：
   - `selectedTrimTransparentBoundsEnabled`
   - `setSelectedTrimTransparentBoundsEnabled()`
5. 内部和序列化继续保留 `use_original_size`，避免兼容风险。
6. 仅在当前图片支持透明通道时动态判断是否禁用，属于后续增强；第一阶段先修正文案。

### P2-2 11 个布尔参数重复显示状态文字和开关

**典型位置：**

- 矢量路径闭合：`app/qml/Main.qml:4960`。
- 去透明留白（当前名为“智能裁剪”）：`app/qml/Main.qml:5055`。
- 文字方向：`app/qml/Main.qml:5465`。
- 文本框自动适配：`app/qml/Main.qml:5504`。
- 图层组展开：`app/qml/Main.qml:5553`。
- 分身启用、自定尺寸、元素铺排：`app/qml/Main.qml:5883`、`5964`、`6007`。
- 文字背景、阴影、发光：`app/qml/Main.qml:6236`、`6297`、`6390`。

**现状：**

一行中同时存在：

- 左侧参数标签。
- 中间“已开启/已关闭”或两个状态的文字。
- 右侧开关。
- 分区标题右侧通常还有一次摘要。

**影响：**

- 同一状态被表达两到三次。
- 中间文字占用属性面板最宝贵的横向空间。
- 文案和开关状态必须同时维护，容易出现不同步。

**修复方案：**

按语义分两类处理：

**真正的二元开关：**

- 路径闭合。
- 图层组展开。
- 分身总开关。
- 文字背景、阴影、发光启用。

只保留“标签 + 开关”，状态由开关、无障碍状态和分区摘要表达。

**两个状态都是工作模式：**

- 横排 / 竖排。
- 手动尺寸 / 自动适配。
- 沿用图层 / 独立尺寸。
- 固定行列 / 填充画布。

改用 `SegmentedControl`，不要再使用状态文字加开关。

可以新增统一组件 `InspectorSwitchRow`，防止后续继续复制“BodyLabel + ToggleSwitch”结构。

### P2-3 文字候选数量在同一分区重复出现

**位置：**

- `app/qml/Main.qml:5265`，分区摘要。
- `app/qml/Main.qml:5356`，分区底部只读行。

**现状：**

“按行随机”模式下，标题摘要显示“X 条候选”，底部又显示“X 条文案”；整段模式则同时出现“整段排版”和“1 条文案”。

删除底部只读“候选/段落”行。候选数量保留在分区摘要即可。若未来需要更强提示，应放在模式控件旁作为小型计数，不再单独占一整行。

**位置：** `app/qml/Main.qml:5748`。

**现状：**

### P3-1 颜色输入组件实现不统一

**位置：**

- 文字填充、背景、阴影使用 `ColorValueField`。
- 描边、颜色叠加、渐变叠加手动组合色块和 `ValueBox`。
- 描边另有独立色板行。

**问题：**

这不是业务状态冲突，但同一“颜色选择 + 十六进制输入”模式存在多套 QML 实现。

**修复方案：**

统一使用 `ColorValueField`。描边快捷色板可以保留，但应作为该颜色字段的快捷预设，而不是另一套颜色编辑器。此项放在功能结构修复之后处理。

## 五、明确保留的双控件

以下组合虽然写入同一字段，但用途不同，不应按“重复”直接删除：

| 组合 | 保留原因 |
| --- | --- |
| 不透明度滑块 + 数值框 | 一个用于快速连续调整，一个用于精确输入 |
| 渐变角度输入 + 方向预设 | 一个支持任意角度，一个提供常用快捷值 |
| 圆角统一值 + 预设 | 一个用于精确输入，一个用于常用快捷值；修复后必须属于同一统一半径 |
| 颜色色块 + 十六进制输入 | 一个用于视觉选择，一个用于精确输入；应由同一组件承载 |
| 图像源路径 + 文件对话框 | 一个支持直接粘贴和检查路径，一个降低文件系统选择成本 |
| 分区摘要 + 分区内控件 | 摘要用于折叠状态，不是第二个编辑入口 |

判断标准不是“是否写入同一字段”，而是两个控件是否服务不同精度或不同输入方式。

## 六、建议实施顺序

### 第一阶段：消除错误状态建模

1. 合并颜色叠加和渐变叠加为单一模式分区。
2. 修复圆角分区的适用范围和统一/独立四角入口。
3. 将分身的固定行列和填充画布改为布局模式，并隐藏无效参数。

这一阶段会改变信息架构和 ViewModel 门面，但不改变底层序列化字段。

### 第二阶段：减少重复表达

1. 将“智能裁剪”改名为“去透明留白”。
2. 删除二元开关旁的重复状态文字。
3. 将横排/竖排、手动/自动、沿用/独立改为分段模式。
4. 删除文字候选数量的重复只读行。
5. 删除翻转的聚合状态文字。

### 第三阶段：组件统一

1. 新增或抽取 `InspectorSwitchRow`。
2. 统一所有颜色编辑为 `ColorValueField`。
3. 为分段模式补齐统一的可访问名称、键盘导航和焦点状态。

7. 保存 `.cmp` 后重新加载，确认旧字段和效果不丢失。

## 九、验收标准

- 同一业务状态只有一个主编辑入口。
- 互斥模式不会再表现为多个独立开关。
- 不显示当前渲染分支不会使用的参数。
- 二元开关旁不再重复显示“已开启/已关闭”。
- 精确输入和快捷预设仍然可用，并明确属于同一参数。
- 不修改 `.cmp` 数据格式，不破坏旧项目和预设。
- 预览、单图导出和批量导出继续使用一致的参数结果。
