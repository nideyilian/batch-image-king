# QML Core Parity Design

## 目标

让 QML 工作台覆盖 QWidget 主程序的核心编辑与导出工作流。完成标准不是出现控件，而是操作真实 `Document` 与图层模型，能够撤销、保存为 `.cmp`、重新加载，并且在预览与导出中产生一致结果。

AI 素材、诊断和非核心辅助工具不属于本轮核心对齐范围。它们只在编辑、编排、数据组合和导出闭环完成后继续处理。

## 实施原则

采用“用户工作流 + 底层依赖”的顺序。先补齐单图层编辑，再开放多选编排；随后接入参考线与预设，最后处理绑定、尺寸匹配和复杂导出。现有 Python 模型是唯一业务事实来源，QML 不复制渲染、分组、绑定或导出算法。

`WorkspaceViewModel` 负责当前文档的编辑命令和可撤销状态；独立 ViewModel 负责列表型或长任务型功能，例如预设、绑定关系、尺寸匹配和多标签导出。QML 使用稳定字符串标识，不直接依赖 Python 枚举值。跨文档状态由 `WorkspaceSessionViewModel` 隔离。

## 功能阶段

1. 图层编辑补齐：文字阴影/发光真实渲染、样式复制粘贴、图片自由裁剪、矢量路径与节点编辑。
2. 编排能力：多选、组/解组、批量显隐/锁定、批量对齐与分布、拖拽排序和图层上下文菜单。
3. 画布效率：标尺、参考线、吸附、视图设置、画布尺寸预设与项目预设管理。
4. 数据组合：绑定组创建/编辑、组合一致性、图层尺寸匹配及自动遮罩参数。
5. 导出对齐：单文档高级批量参数、遍历与预计算、安全限制、多标签选择、独立配置、统一进度和取消。

## 数据与错误处理

所有改变文档内容的命令在修改前保存历史，成功后统一失效渲染缓存并发出选择、图层和预览信号。锁定图层、导出运行中、无效选择或不兼容图层类型必须拒绝操作并给出状态提示。列表管理器的新增、更新和删除使用模型现有校验，QML 只负责收集参数和展示错误。

长任务不阻塞 GUI 线程。单文档与多标签批量导出都复用现有执行器、取消标记和进度信号；QML 不自行循环渲染或写文件。

## 验证标准

每个阶段采用测试先行：ViewModel 合约、撤销/重做、序列化往返、真实渲染或导出副作用、QML 源码烟雾测试。每个 UI 阶段至少检查 1280x760 与 1600x960，确认长中文标签、滚动区域、禁用状态和弹层无溢出。阶段完成后运行 QML 全套与相关核心回归，并创建独立 Git 提交。
