# QML 交互与预览性能设计

## 问题定义

QML 版本当前存在三类可复现卡顿：

1. 首次进入文字图层时，字体目录在 GUI 线程同步扫描，真实交互探针 30 秒超时。
2. 后台预览线程在完整渲染期间持有 `WorkspaceViewModel._document_lock`，UI 修改文档时会等待渲染结束。
3. 每次自动预览都强制执行全质量整帧渲染；新请求只标记 pending，不能取消过期任务，快速连续调参时会积累可见延迟。

此外，`PreviewImageProvider` 对每帧执行两次深拷贝，大画布会造成额外内存带宽和分配压力；透明度滑块每次变化还会触发共享的 `selectionChanged`，导致大量无关 QML 属性重新求值。

## 方案选择

采用两阶段预览管线：交互发生后立即取消旧任务，捕获不可变文档快照，在后台输出限制最大边长的交互帧；用户停止操作后补一张全质量帧。后台任务只读取快照，不长期占用实时文档锁。字体目录始终后台加载，加载完成前仅返回当前字体的轻量占位选项。QImage 在 Python/QML 边界使用 Qt 隐式共享，避免整帧深拷贝。

不在本轮重写为纯 GPU 图层合成器。纯 GPU 架构可能获得更高上限，但会扩大到混合模式、文字、异形、绑定和导出一致性，风险远超本次性能修复范围。

## 数据流

```text
QML 属性/画布操作
  -> WorkspaceViewModel.requestPreview()
  -> 取消上一代 PreviewRenderToken
  -> GUI 线程短暂序列化 Document 快照
  -> QThreadPool 恢复独立 Document
  -> FastRenderer 交互低清帧
  -> PreviewImageProvider 隐式共享 QImage
  -> QML Image 更新
  -> 空闲定时器触发全质量帧
```

## 失败处理

- 快照构建失败时不回退到后台读取实时 Document，避免重新引入锁竞争；保留上一帧并报告预览错误。
- 过期任务通过 token 尽早退出，过期结果不得发布到 provider。
- 高质量帧失败时保留已发布的交互帧。
- 字体扫描失败时保留当前字体和常用字体占位项，不阻塞主界面。

## 验收标准

- QML 真实拖拽探针在 30 秒内完成。
- 后台预览运行期间，UI 线程修改图层不等待完整渲染。
- 连续请求会取消旧任务，只发布当前 generation 的结果。
- 自动预览先发布交互帧，空闲后发布全质量帧。
- 字体属性 getter 不执行同步系统字体扫描。
- QML 专项测试和完整 pytest 通过；若仓库既有脏改动导致失败，需明确区分。
