## 二、为什么没发出去（两个硬阻塞）

### 阻塞 1：没有签名私钥

`BTPW_SIGNING_KEY` 未设置，`update_private_key.txt` 不在本机。

**为什么不能用「无签名清单」凑合发**：
`build.py` 在找不到私钥时会**照样写出 `update.json`**，只打一行 `[错误]`。
这份清单没有 `signature` 字段 —— 已升级到「强制验签」版本的客户端会**静默拒绝**它，
用户看到的是「已是最新版本」，永远收不到 1.4.0。
不是报错，是无声失败，比不发更糟。

### 阻塞 2：`gh` 未登录

`gh auth status` → not logged in。无法用命令行创建 GitHub Release 和上传资产。
（也可以网页手工建 Release，但需要你操作。）

## 三、发版步骤（在有私钥的机器上执行）

```powershell
# 1. 恢复版本号（工作区当前是 1.3.0，需改回 1.4.0）
#    编辑 app/version.py: APP_VERSION = "1.4.0"

# 2. 设置私钥
$env:BTPW_SIGNING_KEY = "C:\path\to\update_private_key.txt"

# 3. 打包 + 刷新并签名清单
python build.py

#    输出里必须出现「更新清单已签名: ...」
#    若出现「[错误] 未找到签名私钥」或「清单签名失败」→ 停下来，不要发布

# 4. 确认清单已更新
#    update/update.json 的 version 应为 "1.4.0"，且 signature 字段非空

# 5. 验证签名（可选但建议）
python tools/sign_update_manifest.py update/update.json --key $env:BTPW_SIGNING_KEY --verify

# 6. 跑一次全量测试确认全绿
python -m pytest

# 7. 提交清单与版本号
git add app/version.py update/update.json 更新日志.md
git commit -m "release: 批图王 v1.4.0（刷新并签名更新清单）"

# 8. 推送
git push origin main
```

## 四、v1.4.0 包含什么（给更新说明用）

### 大画布拖动：3.8 fps → 33 fps

| 画布（8 图层） | 之前 | 现在 |
|---|---|---|
| 1080×1350 | 32 fps | **51 fps** |
| 2000×2500 | 11 fps | **90 fps** |
| 4000×5000 | **3.8 fps** | **33 fps** |

两个原因都修了：每合成一层复制整张画布（4000×5000 是 76MB/层）、
拖一层却重算整张画布。

### JPEG 导出快 8.7 倍

424 ms → 49 ms。真凶不是编码，是「压平到白底」走了 float64 线性空间混合
（418ms），换成 `Image.alpha_composite` 只要 9ms。

### 内存不再持续增长

连续 80 次预览内存增量 **0 MB**（之前会涨到 1GB 以上）。
4GB 小内存机器上缓存会自动收缩到原来 1/4。

### 导出更顺

- 导出并发从 CPU 60% 放宽到 75%（`BTPW_BATCH_CPU_CAP=0.6` 可还原）
- 导出期间预览自动降级，不再和导出抢 CPU
- 导出启动前会提示「启动导出进程（首次约 1 秒）」，不再毫无动静
