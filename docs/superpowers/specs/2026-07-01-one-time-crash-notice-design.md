# 闪退后一次性中文提示设计

## 目标

程序异常退出后，下一次启动只弹出一次中文提示。提示先用口语说明发生了什么，再展示日志中能提取到的具体原因。若没有崩溃堆栈，也要提示上次未正常关闭，并说明可能是强制结束、断电或系统资源不足。

## 状态模型

在用户日志目录 `~/.config/批图王/logs` 保存 `last_run_state.json`，内容包括：

- 本次运行唯一 ID。
- 启动时间。
- 本次 `crash_*.log`、`app_*.log` 路径。
- 状态：`running` 或 `clean_exit`。
- 是否已消费异常提示。

启动顺序：

1. 在覆盖状态文件前读取上一次状态。
2. 若上次状态为 `running` 且未消费，生成待显示的异常报告。
3. 立即原子写回“已消费”，保证该报告只显示一次。
4. 为本次启动写入新的 `running` 状态。
5. UI 显示后，用单次定时器弹出报告，避免阻塞启动画面。

正常退出时把本次状态更新为 `clean_exit`。任务管理器强杀、断电、原生访问冲突等无法执行清理，因此状态会保持 `running`。

## 原因解析

解析只读取上次状态记录的日志，避免把更早的错误误认为本次闪退。

优先级：

1. `crash` 日志中的 `Windows fatal exception`、线程栈和 `Current thread`。
2. `crash` 日志中的未捕获线程异常、Qt fatal、unraisable exception。
3. `app` 或 `stderr` 中最后一个 Traceback、CRITICAL、ERROR。
4. 只有运行标记时，归类为“未记录到具体原因”。

常见原因转为口语中文：

- `access violation`：程序访问了无效内存，通常与原生图像处理、Qt 控件生命周期或并发有关。
- `MemoryError` / 内存不足：处理图片时内存不够。
- Python Traceback：显示异常类型、最后一条错误信息和最接近业务代码的栈位置。
- 无明确日志：可能是强制结束、断电或系统资源不足。

解析结果限制长度，完整日志路径保留在弹窗详细信息中。

## 弹窗

标题：`检测到上次异常退出`

正文结构：

```text
上次程序在运行时突然退出了。

可能原因：程序访问了无效内存。
具体位置：图层面板重建（app/ui/layer_panel.py:201）
发生时间：2026-07-01 10:10:04
```

弹窗使用 `QMessageBox.Warning`，只有“知道了”按钮。详细信息包含技术摘要和相关日志路径，便于用户复制给开发者。

## 组件边界

新增 `app/utils/crash_session.py`，只负责状态文件、日志解析和中文报告生成，不依赖 PySide6。`main.py` 负责调用它并显示 QMessageBox。

独立导出 worker 不创建主程序运行状态，避免 worker 异常导致主程序下次启动误报。

## 错误处理

状态文件损坏、目录无权限或日志无法读取时，不阻止程序启动。原子写入失败只记录警告。读取到损坏状态时忽略并为本次运行重新建档。

## 测试与完成标准

1. `running` 状态在下次启动生成一次报告，第二次读取不再生成。
2. `clean_exit` 状态不生成报告。
3. access violation 日志生成口语中文原因、业务栈位置和日志路径。
4. 没有具体日志时生成强制结束/断电/资源不足提示。
5. 正常退出正确标记 `clean_exit`。
6. export worker 分支不创建主程序运行状态。
7. 新测试、现有启动/崩溃相关测试及 Python 编译检查通过。
