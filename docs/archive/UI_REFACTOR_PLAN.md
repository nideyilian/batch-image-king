# 界面重构方案评估

> 2026-10-28 · 针对「组件无统一规范 / 构图随机 / 尺寸间距随意」的实测与选型

## 一、先承认前几轮的错

前一轮 P2/P3 我做的是：统一控件高度、去描边、清理硬编码色值。

**这是在给一个没有地基的房子刷漆。**

我自己测出来的数（见第二节）证明：项目缺的不是「颜色不对」，而是
**没有任何东西强制约束尺寸与间距**。P2 只压住了「我看到的那几个控件」，
没压住的还有 37 种高度。这是我的方法问题——我一直在修复症状。

---

## 二、现状实测数据（不是印象，是量出来的）

### 2.1 尺寸失序

一个新建文档的主窗口，170 个可见控件：

| 维度 | 实测 | 判断 |
|---|---|---|
| 控件高度种类 | **37 种** | 16/18/24/26/30/31/36/38/44 混用 |
| 按钮高度 | **5 种** | 18 / 26 / 36 / 38 / 44 |
| layout spacing | **7 种** | 0 / 2 / 3 / 4 / 5 / 6 / 8 |
| layout 边距 | **9 种** | 含 `(8, 4, 7, 4)`、`(8, 4, 7, 4)` 这类非对称值 |

对照参考值（业界成熟系统）：

| 系统 | 尺寸档 | 间距档 |
|---|---|---|
| Ant Design | 3 档（24/32/40） | 8 档（4/8/12/16/24/32/48/64） |
| TDesign | 3 档（24/32/40） | 6 档 |
| Bootstrap 5 | 2 档 | 6 档（0.25rem 步进） |
| Radix / Chakra | 2~3 档 | 6 档 |

**规范系统里，高度档位 ≤ 3、间距档位 ≤ 8。我们 37 种高度。**

### 2.2 样式无单一真源

| 项 | 实测 |
|---|---|
| `setStyleSheet` 调用点 | **67 处，散在 37 个文件** |
| 全局 QSS | 30.3KB / 228 条规则（`provider.py` 871 行） |
| 面板自带 QSS | `design_tokens.control_qss` 等，绕过全局令牌 |
| 内联 QSS | 各对话框各写一套（如旧 `minimal_text_editor_dialog` 整套配色） |

**三层样式叠加，越内层优先级越高。全局改不动内联——这是「改了没效果」的根因。**

### 2.3 图标系统

有 SVG 图标系统（`ICON_SVGS`，SF Symbols 风格 24×24），覆盖 51 个。

问题不是「没有图标库」，而是**两套混用 + 线宽不一致**：

- `delete` 是实心填充垃圾桶，其余是线条
- `refresh` / `undo` / `redo` / `random` 用字体字符（粗细与 SVG 完全不同）
- `save` 实心软盘、`fit` 虚线框
- 线宽 1.5~2.5 之间跳

### 2.4 关键实验：缺的是纪律，不是库

同一组控件，只换全局 QSS：

| | 原主题 | 换「纪律化 QSS」后 |
|---|---|---|
| QPushButton | 38 | **28** |
| QLineEdit | 30 / 24 | **28** |
| QSpinBox | 30 | **26** |
| QComboBox | 30 | **28** |

**换 QSS 立刻就能统一。** 说明技术上没有任何障碍，
真正的问题是：**没有一份被强制执行的规格 + 67 处内联样式在破坏它**。

## 三、候选方案实测（都真实装过、跑过、截过图）

### 方案 A：QFluentWidgets（PySide6-Fluent-Widgets）

- 效果：业内最好，仿 WinUI 3 / Fluent Design，170+ 组件
- **许可证：GPLv3 非商用；商用需购买**，Python 版 **$399 / $599 / $729**
- 架构：整套 Framework（`FluentWindow`、`NavigationInterface`），
  不是样式层替换

**判断：❌ 不推荐。**
1. 许可证要花钱，且 GPLv3 对闭源分发有传染性
2. 它是「换框架」不是「换样式」——接入意味着重写所有界面代码
3. 你的项目有 40+ 对话框、676 个控件，迁移成本以月计

### 方案 B：qt-material（已实测）

- 许可证 BSD-2，免费商用，26 套主题
- 实测截图：**三个按钮（主/次/危险）长得完全一样**，
  QComboBox 样式断裂、滑块高度异常
- 设计假设是「一个 accent 色统一全局」，**没有按钮变体概念**

**判断：❌ 不推荐。**
对编辑器工具来说粒度太粗——主按钮和删除按钮必须可区分，
这是功能需求不是审美偏好。

### 方案 C：Qlementine

- MIT，现代 QStyle，效果接近 Fluent 但更克制
- **需要 C++ 编译（CMake 3.21+ / Qt 6.8+）**，无 Python 绑定

**判断：⚠️ 有条件可行，但不推荐。**
你的项目是纯 Python + PyInstaller 打包，引入 C++ 编译链会让
打包流程复杂度大幅上升，收益不匹配。

### 方案 D：qtawesome（图标，已实测）

- MIT，内含 FontAwesome 5/6、Material Design Icons(6997)、
  Phosphor(4470)、Remix(2271)、Codicons(569)
- **实测 30/30 语义全部命中**，且同属 FontAwesome 6 Solid，
  线宽、圆角、视觉重量天然一致

**判断：✅ 强烈推荐，只用于图标。**
这是唯一「装上就能用、立刻解决一个真问题」的库。
建议映射到 `mdi6`（Material Design Icons，6997 个，覆盖面最广，
线条风格最接近你现在的 SVG 设定）。

### 方案 E：BreezeStyleSheets

- MIT，纯 QSS，Breeze/BreezeDark 风格，为 KDE 桌面开发
- 网络受限未能拉取实测

**判断：⚠️ 备选。**
它是「另一个完整风格」，套上去等于把界面变成 KDE 桌面软件的样子，
和你要的品牌感未必一致。作为「QSS 结构参考」有价值。

## 四、推荐路线

### 核心判断

**不要引入整套 UI 框架。引入「一份被强制执行的规格 + 一个图标库」。**

理由：实测证明换 QSS 就能统一尺寸，成本极低；
而换框架要重写 40+ 对话框，成本以月计，收益是「长得像 Windows 原生」。

### 分三步

**Step 1：建规格（1 份文件，锁死所有数值）**

新增 `app/ui/design_spec.py`，定义**唯一**的尺寸与间距阶梯：

```
高度档：28（默认）/ 24（紧凑）/ 36（主操作）       ← 3 档，对齐 Ant/TDesign
间距档：0 / 4 / 8 / 12 / 16 / 24                  ← 6 档，4px 栅格
边距档：8 / 12 / 16 / 24                          ← 4 档
圆角：4 / 6 / 8 / 12                              ← 4 档
字号：11 / 12 / 13 / 15 / 18 / 24                 ← 6 档
图标：16 / 20 / 24                                ← 3 档（WCAG 2.5.8 最小 24）
```

配套一条**契约测试**：遍历真实窗口，断言
「可见控件的 height 只能落在 {28,24,36} 内」——
不合规立刻失败。这是唯一能防止再次跑偏的机制。

**Step 2：消灭内联 QSS（67 处 → 0）**

按优先级：
1. 先删「整套内联 QSS」的对话框（直接改 `variant` 属性走全局）
2. 再改「单个 setStyleSheet 设颜色」的（换令牌）
3. 最后处理确实需要局部样式的（提成全局规则 + 属性选择器）

**Step 3：图标换 qtawesome（MIT，零成本）**

- `pip install qtawesome`
- 把 `ICON_SVGS` 的 51 个 key 映射到 `mdi6.*`
- 保留 SVG 作为降级（不删旧代码，只改取图路径）
- 顺带解决字体字符混用问题

### 验证标准

1. 契约测试：可见控件高度种类 ≤ 3，spacing 种类 ≤ 6
2. `setStyleSheet` 调用点从 67 降到 ≤ 10
3. 图标全部来自同一图标集（无字体字符混用）
4. 100% / 125% / 150% DPI 下无溢出、无截断
5. 现有 748 项测试全绿

## 五、需要你决策的点

| 议题 | 选项 A | 选项 B | 我的建议 |
|---|---|---|---|
| 要不要买 QFluentWidgets | 花钱买（$399+），效果最好 | 不买，自己立规范 | **B**。你要的是「统一」，不是「像 Windows」 |
| 基准高度 | 28 / 32 / 36 三档 | 只留 32 一档 | **三档**。编辑器需要紧凑区和主操作区区分 |
| 图标集体 | Material Design Icons(6997) | FontAwesome 6(2000+) | **mdi6**，覆盖面广、线条细，更贴近工具软件 |
| 是否保留亮色主题 | 只做暗色 | 双主题 | **只做暗色**（与既有决策一致） |

---

## 六、一句话总结

**你缺的不是组件库，是「一份不许随手加数字」的规格 + 一个能自动抓违规的测试。**

组件库解决的是「从零搭界面」，你的问题是「已经有界面但失序」——
后者的解药是收敛，不是新增一层依赖。
