# 深色工作台设计规范覆盖审计

审计日期：2026-08-04
参考来源：`birobirobiro/awesome-shadcn-ui`、shadcn/ui 组件语义、当前 PySide6 代码。

## 1. 结论

当前设计系统已经从“有令牌和 Showcase，但业务采用很少”升级为两层覆盖：

1. 全局语义覆盖：应用启动后，27 个 `QDialog` 子类及历史面板由 `SemanticWidgetPolisher` 自动补齐按钮、进度、分组和标签页语义。
2. 显式组件覆盖：新增界面可使用完整公共组件；主窗口、新建画布、批量导出、预设管理和图层属性面板已经显式标注关键角色。

因此，所有窗口都能获得统一基础状态，但部分低频窗口仍没有改为显式公共组件。兼容覆盖不应被误认为迁移完成。

## 2. 当前指标

| 指标 | 当前值 | 说明 |
| --- | ---: | --- |
| 公共组件导出 | 72 | 类、工厂、常量和兼容别名 |
| 原生 QDialog 子类 | 27 | 全部由应用级适配器覆盖 |
| 语义属性设置 | 253 | `role/variant/uiSize/status` 静态计数 |
| 显式导入组件库文件 | 7 | 新代码与高频试点 |
| 业务 UI 十六进制命中 | 122 | 含画布内容色、色板、预览绘制和遗留局部 QSS |
| 业务 `setStyleSheet` | 92 | 含自绘、尺寸覆盖和遗留模块样式 |

十六进制和 `setStyleSheet` 的总数不能直接等同于违规数。以下属于允许范围：

- 用户选择色、渐变、描边和图像内容色。
- Canvas、色板和预览控件的实际绘制颜色。
- 仅包含尺寸、布局的作用域化 QSS。
- 从 `Theme` 或 `Tokens` 生成的兼容样式。

仍需迁移的是在业务文件中固定界面背景、文本、边界或状态色的局部 QSS。

## 4. 组件映射

### 已实现

- 操作：Button、IconButton、ButtonGroup、Toggle、ToggleGroup、SegmentedControl、Kbd。
- 表单：Input、Textarea、NumberInput、Select、ComboBox、MultiSelect、Checkbox、RadioGroup、Switch、Slider、Field、InputGroup、ColorSwatch。
- 布局：Card、Tabs、Accordion、ScrollArea、Resizable、Sidebar、Separator、AspectRatio、Sheet。
- 弹层：Dialog、AlertDialog、Popover、DropdownMenu、ContextMenu、CommandPalette。
- 反馈与数据：Badge、Alert、Toast、ProgressBar、Spinner、Skeleton、EmptyState、Table、FileDropZone。

### 有意不采用

Avatar、Calendar、Carousel、Breadcrumb、Pagination、OTP、Marquee、NavigationMenu 等没有当前工作流，不为了组件数量而引入。

### 领域组件来源

上游清单中的 file-uploader、image-upload、image-crop、drag-to-resize-sidebar、command palette 和 confirm dialog 与批图王相关。当前只吸收其交互模式：文件拖放、可调分栏、命令筛选、确认语义。图片裁剪继续由画布和图层模型负责，不复制 Web 组件逻辑。

## 5. 单一事实来源

```text
design_tokens.py
  -> theme/tokens.py
  -> theme/provider.py + theme/polisher.py
  -> components/*
  -> business UI
```

`DialogA2.stylesheet()` 现为兼容方法，返回 `provider.py` 生成的全局 QSS，不再维护第二份颜色。

`Button` 尺寸动态属性已由 `size` 修正为 `uiSize`。Qt 的 `size` 是内建 `QSize` 属性，旧写法不会产生预期的 QSS 选择器。

## 6. 剩余债务

### P1：低频编辑器

以下模块仍有较多固定界面色或局部样式，应在下一次功能触达时迁移：

- `integrated_text_editor_dialog.py`
- `simple_text_editor_dialog.py`
- `preset_panel.py`
- `preset_store_dialog.py`
- `status_indicators.py`

### P2：兼容面板

- `CollapsibleGroupBox` 仍从 `design_tokens` 生成局部 QSS。
- `property_panel_a2.py` 和部分文字面板仍是历史兼容层。
- `ui_primitives.py` 的旧 Toast/EmptyState 与新组件并存。

处理原则：先迁移调用方，再删除兼容层；不得为了数字好看一次性改写成熟业务窗口。

### P3：皮肤切换产品化

本阶段只有深色工作台。新增皮肤前必须完成：

1. 低频窗口固定界面色清理。
2. Windows 125%/150% 缩放视觉回归。
3. 皮肤持久化和启动失败回退。
4. 用户内容色与主题色边界测试。

## 8. 后续审计方法

审计时应同时报告三组数据：

1. 全局覆盖：应用级主题与语义适配是否安装。
2. 显式采用：业务文件是否导入公共组件或设置语义属性。
3. 遗留债务：固定界面色和局部 QSS 是否仍存在。

只报告其中一项会造成误判。全局覆盖保障一致底线，显式采用保障可维护性，遗留债务决定未来皮肤的真实成本。
