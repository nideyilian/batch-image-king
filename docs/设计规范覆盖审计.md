# 设计规范与组件库覆盖审计（批图王）

> 目标：核查 `docs/DESIGN_SYSTEM_SHADCN.md` 定义的设计规范 + `app/ui/components` 组件库，
> 是否覆盖程序的**全部界面（含弹窗）**。
> 审计日期：2026-08-04 ｜ 范围：`app/ui/` 全部 78 个文件 + `main.py`

---

## 一、结论（先说结论）

**没有完整覆盖。** 设计规范（shadcn 令牌 + 全局 QSS）在「暗色主题的基线一致性」上确实兜底了所有 QWidget 窗口，
但**组件库几乎没有落地**，且代码库里还并存着**第二套硬编码样式系统 `DialogA2`**，与设计规范「单一真源 / 禁止第三套 QSS」的准则直接冲突。

| 维度 | 预期（设计规范宣称） | 实际覆盖 | 是否达标 |
|---|---|---|---|
| 全局令牌 / 暗色 QSS 基线 | 所有 QWidget 窗口自动继承 | 已通过 `main.py:226` `CursorDarkTheme.apply_to_application` 全局应用 | ✅ 基线达标 |
| 语义组件库（`app.ui.components`） | 新界面一律取件 | 仅 **1 个弹窗**（`new_canvas_dialog`）+ 画廊采用，其余 26 个弹窗均未用 | ❌ 严重缺口 |
| 单一样式真源 | 仅 `theme/tokens.py` + 全局 QSS | 另有 `dialog_a2.py` 硬编码一套独立令牌并 `setStyleSheet` 到弹窗 | ❌ 违反准则 |
| 模态反馈用 `Alert` 行内提示 | 替代 `QMessageBox` | `QMessageBox` 仍被使用 **200+ 处**，0 处迁移 | ❌ 缺口 |
| 双主题（暗/亮）切换 | 切令牌即全程序换肤 | 大量界面写死 `#hex` / 内联 `setStyleSheet`，亮色主题对其**不生效** | ❌ 名存实亡 |

## 二、设计系统预期架构（规范声称）

按 `DESIGN_SYSTEM_SHADCN.md`：

- `app/ui/theme/tokens.py` 是**唯一颜色/尺寸真源**；
- `app/ui/theme/provider.py` 由令牌生成全局 QSS（`build_global_stylesheet()`）；
- `app/ui/dark_theme.py` 在 `get_complete_style()` 末尾**追加**该 shadcn 层；
- `main.py` 启动时 `CursorDarkTheme().apply_to_application(app)` 全局应用；
- 业务界面只从 `app.ui.components` 取件（`Button/Card/Input/Alert/Switch/...`），**禁止写死色值、禁止第三套 QSS**。

理论上：任何新窗口/弹窗只要用 QWidget 体系，即自动获得统一外观。

---

## 三、实际现状：三套并行样式系统

### 系统 A —— 设计规范（令牌 + 全局 QSS + 组件库）★ 应作为唯一真源
- 落地位置：`app/ui/theme/*`、`app/ui/dark_theme.py`、`app/ui/components/*`
- **实际采用的业务界面**：`app/ui/new_canvas_dialog.py`（试点）、`app/ui/showcase.py`
- 搜索 `from app.ui.components import` 全 `app/ui` 仅命中 **4 个文件**（含组件自身与 showcase）

### 系统 B —— `DialogA2`（`app/ui/dialog_a2.py`）⚠ 冲突的第二套
- 自我定位：「Reusable Dialog A2 styling tokens for modal windows」
- 它**自己硬编码一套色值**（`PANEL_BG="#181818"`、`CARD_BG="#202123"`、`ACCENT="#2F9CF4"` … 共 30+ 常量），
  注释声称「与 design_tokens 对齐的语义别名（单一真源）」——实为**复制而非引用**，与 A 系统会漂移。
- 通过 `DialogA2.apply(dialog)` 对弹窗**单独 `setStyleSheet`**，覆盖全局 QSS 继承链，
  等于在全局 shadcn 层之上又叠了一层选择器（`QDialog[dialogA2="true"] ...`），直接违反准则「不要新建第三套 QSS」。
- 仅支持暗色硬编码值，**不支持亮色主题切换**。

### 系统 C —— 原生控件 + 全局 QSS 基线（无组件、无 DialogA2）
- 绝大多数弹窗当前处于此状态：用 `QPushButton/QLineEdit/QComboBox`，仅由全局 QSS 兜底基础外观，
  未设置 `variant/role`，因此**没有** default/ghost/destructive 等语义变体，也没有 `Card/Alert/Switch` 组件化结构。

## 六、关键缺口清单（按严重程度）

1. **【严重】组件库采用率 3.7%**：26/27 弹窗 + 全部内嵌面板未使用 `app.ui.components`，
   语义组件（`Button` 变体、`Card`、`Alert`、`Switch`、`Badge`、`Tabs` 等）几乎形同虚设。
2. **【严重】并存第二套硬编码样式 `DialogA2`**：自带 `setStyleSheet` 与重复色值，违反规范
   「单一真源 / 禁止第三套 QSS」，且与亮色主题不兼容。
3. **【严重】双主题切换形同虚设**：`theme/tokens.py` 已支持 `set_mode("light")`，但 14+ 弹窗与多个面板
   写死 `#hex` / 内联样式，亮色下会错乱或保持暗色。
4. **【中等】`QMessageBox` 模态反馈 200+ 处未迁移**：规范第 6.5 条要求改为行内 `Alert`，目前 0 迁移。
   涉及 `binding_manager_dialog`、`batch_export_dialog_progress`、`canvas_preset_dialog` 等大量弹窗。
5. **【中等】开关控件可能未统一**：规范强制用 `Switch`（A2Switch 风格）而非原生 `QCheckBox`，
   需逐弹窗核对（如 `add_layer_dialog`、`layer_effects_dialog` 等仍用 `QCheckBox`）。
6. **【低】原生 `QDialogButtonBox`**：批量导出系列用 `QDialogButtonBox`，未替换为语义 `Button` 变体，
   默认/取消按钮的 `variant` 语义未体现。

## 七、迁移优先级建议

**P0（打通单一真源）**
- 废除/收敛 `dialog_a2.py`：将其色值改为从 `Theme` 读取，或直接删除，让 `DialogA2.apply` 改用全局 QSS。
- 给全部 27 个弹窗的基类统一接入组件库（建议新增 `app/ui/components/dialog.py` 已提供的 `Dialog` 基类，
  让既有弹窗改为继承它，自动获得 `button_row([...])` 等语义布局）。

**P1（组件化试点扩展）**
- 按 `new_canvas_dialog.py` 模式，依次迁移高频弹窗：
  `add_layer_dialog` → `resize_canvas_dialog` → `layer_effects_dialog` → `canvas_preset_dialog`
  → `preset_manager_dialog` → `batch_export_dialog*` → `multi_tab_export_dialog`。
- `Button` 替代 `QPushButton` 并标注 `variant`；分组用 `Card`；状态提示用 `Alert`；开关用 `Switch`。

**P2（清理硬编码，恢复双主题）**
- 全量替换内嵌 `#hex` / `setStyleSheet` 为 `Theme.get(...)` / 全局 QSS role。
- 迁移 `QMessageBox` → `Alert`（行内）或统一封装 `show_alert()` 助手。

**P3（验证）**
- `python app/ui/showcase.py` 走查组件画廊；
- `Theme.toggle_mode()` 切换亮色，逐个弹窗验证无错乱；
- `python main.py` 跑一遍新建/保存/导出/批量导出流程，确认无回归。

---

## 八、一句话总结

> 设计规范把「全局 QSS 兜底」做扎实了，但**组件库只落在 1 个试点弹窗**；与此同时代码里还长着
> **`DialogA2` 这第二套硬编码样式**，加上 **14+ 弹窗与多个面板直接写死颜色**，导致
> 「单一真源 / 双主题 / 语义组件」三大承诺目前**均未兑现**。建议以 P0 收敛 `DialogA2` 为起点，
> 按 `new_canvas_dialog` 模板逐弹窗迁移。
