## 问题：build.py 会覆盖签名

`write_update_manifest` 每次发版都重写 update.json，而签名是对内容算的 ——
重写必然让旧签名失效。靠"打完包记得再签一次"迟早会漏，而漏签的后果极隐蔽：
不报错，只是所有已升级客户端静默拒绝更新（用户看到"已是最新版本"）。

现在 build.py 自己签：
- `_find_signing_key`：环境变量 BTPW_SIGNING_KEY > 当前目录 > 项目根
- `_sign_manifest_payload`：签名成功打印「更新清单已签名: ...」；
  无密钥或密钥损坏时**不中断打包**，但打 [错误] 提示"本次发布不带有效签名"

## 顺带修一个真实陷阱：警告被静默吞掉

build.py 顶层是 `from app.utils.print_utils import safe_print as print`，
而 safe_print 默认**只放行**带"错误/失败/Exception/Traceback"关键词或
以 [ERROR]/[CRITICAL]/[严重错误] 开头的消息。

我最初写的警告是「⚠️ 未找到签名私钥…」，不含任何关键词 → **完全看不到**。
打包的人会以为签名成功，实际发出去的是未签名清单。

实测对比：
    _should_print('[错误] 未找到签名私钥')  → True
    _should_print('⚠️  未找到签名私钥')      → False

统一改成 [错误] 前缀。

## 测试

新增 tests/test_build_manifest_signing.py（7 项）：
- 有密钥 → 自动签名且能验过
- 签名覆盖 download_url（改地址必须验不过）
- 无密钥 → 不签 + 必须给出可执行提示
- 密钥损坏 → 不抛异常 + 提示后果
- 密钥查找顺序：环境变量 > cwd > 项目根
- 签名不丢失业务字段
- **警告能穿透 safe_print 过滤**（把 [错误] 能打印、⚠️ 会被吞都写成断言，
  防止以后又改回去）

注：这几条测试不能用 capsys 断言输出 —— safe_print 的 file 参数在模块导入时
就绑定了当时的 sys.stdout，pytest 替换后抓不到。改用 `_should_print` 判定
"会不会被打印"，这才是稳定的判据。
